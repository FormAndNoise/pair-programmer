# Security Architecture & Threat Model

This document defines the security boundaries, threat model, and operational controls of the Dual-Model Pair Programming Agent.

## 1. Threat Model

The harness executes untrusted code and tool calls generated by external Large Language Models (LLMs). The primary adversary vectors are:

1. **Indirect Prompt Injection & Malicious Model Output**: A compromised or hallucinating LLM attempts to execute arbitrary host commands, exfiltrate environment credentials, or tamper with test suites to force false-positive completions.
2. **Sandbox Escape & Resource Exhaustion**: Generated code attempts path traversal (`../`), symlink races (TOCTOU), fork bombs, memory exhaustion, or infinite output floods.
3. **Cross-Site WebSocket Hijacking (CSWSH) & Local API Abuse**: A malicious web page open in the operator's browser attempts to connect to `127.0.0.1:8000` to steer the sprint, starve rate limits, or read workspace source code.
4. **Terminal & Log Injection**: Model output or filenames contain ANSI/OSC escape sequences designed to spoof terminal prompts or manipulate the operator's clipboard.

## 2. Execution Sandbox Boundaries

### 2.1 Docker Container Sandbox (`DockerSandboxRunner` — Default for Live Sprints)

Live sprints default to `SANDBOX_MODE=docker`. Each `run_command` invocation executes inside a fresh, disposable container with the following controls:

| Control | Flag / Mechanism | Purpose |
|---|---|---|
| Digest-Pinned Default Image | `DEFAULT_PRODUCTION_IMAGE` (`python:3.11-slim@sha256:db20d850...`) | Prevents mutable tag drift; `SANDBOX_REQUIRE_DIGEST=1` enforces `@sha256:<64-hex>` on custom images. |
| Validated Bind Mount | `--mount type=bind,source=...,target=/workspace` | Validates host paths (rejecting `/`, `C:\`, `Path.home()`, commas, control chars, and extra colons). |
| Network Air-Gap | `--network none` | Blocks outbound data exfiltration and arbitrary downloads. |
| Read-Only Rootfs | `--read-only` + `--tmpfs /tmp:rw,noexec,nosuid,size=64m` | Prevents container rootfs persistence and binary drops in `/tmp`. |
| Unprivileged User | `--user 65534:65534` | Runs container processes as `nobody:nogroup` instead of `root`. |
| Capability Drop | `--cap-drop=ALL` + `--security-opt no-new-privileges` | Drops all Linux capabilities and blocks setuid privilege escalation. |
| Resource Ceilings | `--memory 512m --memory-swap 512m --cpus 1.0 --pids-limit 128 --ulimit nofile=1024:1024` | Mitigates fork bombs, swap thrashing, and descriptor exhaustion. |
| Init & Reaping | `--init` + `--rm` + startup `_reap_orphaned_containers()` | Reaps zombie processes and removes containers on timeout or crash. |

### 2.2 Local Process Sandbox (`SandboxRunner` — Explicit Opt-In Only)

When `SANDBOX_MODE=local_process` is used:
- **Live mode refuses to start without `--unsafe-local`** and prints a prominent warning banner whenever `local_process` is active (including `--mock`).
- **No OS-level filesystem or network namespace isolation exists** in `local_process` mode. Path confinement (`resolve_path`) applies only to the structured file tools (`read_file`, `write_file`, `patch_file`, `list_dir`), **not** to arbitrary Python subprocesses started via `run_command`, which execute with the host user's filesystem and network privileges.
- Workspace roots (`--sandbox`) are validated via `validate_workspace_path()`, which rejects filesystem roots (`/`, `C:\`) and `Path.home()`.
- Commands execute with `shell=False` (`_parse_command_argv` preserves Windows backslash paths and resolves `python`/`python3` to `sys.executable`), Windows Job Object containment (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`) / POSIX process-group kill on timeout, and bounded pipe-drain threads.

### 2.3 Allowlist Environment Scrubbing

`build_sanitized_environment()` constructs subprocess environments from a strict platform-aware **allowlist**:
- Permitted host keys: `PATH`, `LANG`, `LC_ALL`, `LC_CTYPE`, `TERM`, `TZ`, plus required Windows system variables (`SYSTEMROOT`, `WINDIR`, `COMSPEC`, `PATHEXT`, `OS`, `SYSTEMDRIVE`, `NUMBER_OF_PROCESSORS`, `PROCESSOR_ARCHITECTURE`).
- All API keys (`ANTHROPIC_*`, `GEMINI_*`, `OPENAI_*`, `OPENROUTER_*`, `GROQ_*`), cloud/VCS tokens (`AWS_*`, `GCP_*`, `GOOGLE_*`, `AZURE_*`, `GITHUB_*`, `GH_*`, `GITLAB_*`, `HF_*`), Git hooks/SSH overrides (`GIT_SSH_COMMAND`, `GIT_ASKPASS`, `GIT_EXEC_PATH`, `GIT_EXTERNAL_DIFF`, `GIT_TEMPLATE_DIR`, `GIT_CONFIG_*`), proxy settings, and dynamic-loader variables (`LD_*`, `DYLD_*`, `PYTHONSTARTUP`, `PYTHONINSPECT`, `PYTHONPATH`) are stripped.
- `HOME`, `USERPROFILE`, `TMPDIR`, `TEMP`, and `TMP` are pinned to `<workspace>/.tmp`, with `PYTHONNOUSERSITE=1` and `PYTHONDONTWRITEBYTECODE=1`.

### 2.4 Path Confinement, TOCTOU Hardening & Resource Caps

- `resolve_path()` resolves target paths against `workspace_dir` and raises `PermissionError` on traversal outside the workspace.
- `read_file`, `write_file`, and `patch_file` walk every path component from `workspace_dir` using `os.lstat`, verify parent directory inodes before and after `mkdir`, `NamedTemporaryFile`, and `os.replace`, and open files with `O_NOFOLLOW` + `os.path.samestat(lstat, fstat)`.
- `write_file` rejects NUL (`\x00`) bytes and reports UTF-8 byte counts; `patch_file` enforces the 1 MiB (`MAX_WRITE_BYTES`) cap on the final UTF-8 payload.
- `list_dir` uses `os.scandir` + `os.lstat`, skips symlinks, and caps output at `MAX_LIST_DIR_ENTRIES = 1000` and `MAX_TOOL_OUTPUT_CHARS = 85_000`.
- `PairProgrammingEngine` enforces an aggregate per-phase conversation history budget (`MAX_HISTORY_CHARS = 120_000`), compacting older tool outputs to prevent context exhaustion.

## 3. Definition of Done (DoD) & Adversarial Review Integrity

To prevent an Implementer model from gaming the quality gates:

1. **RED-Phase Test & Config Pinning**: Immediately after the RED phase, `BacklogManager.snapshot_test_hashes()` records SHA-256 digests of all discovered test files (`tests/**/test*.py`, `test*.py`) and test discovery configuration files (`pyproject.toml`, `setup.cfg`, `unittest.cfg`, `pytest.ini`, `tox.ini`). When `require_test_pinning=True`, a missing or modified snapshot fails `verify_dod()`.
2. **Test-Command Allowlist & Anti-Shadowing**:
   - `verify_dod()` accepts only `ALLOWED_TEST_COMMANDS` (`python -m unittest` and standard `discover` variants), rejecting arbitrary `-c` commands before execution.
   - `verify_dod()` blocks any `*.pth` file and any workspace file or package shadowing `unittest`, `compileall`, `site`, `sitecustomize`, `usercustomize`, or core stdlib modules (`sys`, `os`, `importlib`, `ast`, `subprocess`, `shutil`, `pathlib`, `types`, `io`, `re`, `json`, `hashlib`, `tokenize`, `traceback`, `linecache`, `warnings`, `collections`, `functools`, `itertools`, `abc`, `contextlib`).
3. **Outside-In UX Evaluator (`OutsideInUXEvaluator`)**:
   - Contract arguments and expected values are parsed strictly with `ast.literal_eval` (never `eval()`), rejecting executable expressions.
   - If a target function is defined in multiple workspace modules, the evaluator fails closed with an ambiguity barrier unless the contract qualifies the module path (`pkg.mod.func(...)`).
   - Unrecognized prose contracts fail closed (`passed=False`) rather than falling back to unit tests.
4. **Structured Cross-Model Review**:
   - Self-approval (`test_model == impl_model` or mismatched response model attribution) is rejected.
   - Untrusted workspace source files are wrapped in `<untrusted_workspace_code>` delimiters.
   - `_is_review_approved()` parses an explicit `VERDICT: LGTM` / `VERDICT: REJECT` line (and rejects negations, caveats, or quoted/code-fenced `LGTM` tokens). Because no prompt structure can guarantee immunity against all LLM prompt injection, model review is treated as one signal alongside the deterministic DoD gates.

## 4. Model Gateway & Web Studio Security

1. **Endpoint Credential Guard (`R-11`)**: `ModelGateway` validates `OPENAI_BASE_URL` against `DEFAULT_ALLOWED_OPENAI_HOSTS` (`api.openai.com`, `openrouter.ai`, `api.groq.com`). Redirecting API credentials to a custom or local endpoint raises `ValueError` before any HTTP request unless `ALLOW_CUSTOM_BASE_URL=1` is set.
2. **Error Redaction & Typed Retry Classification (`R-19`)**: `_redact()` strips `Bearer` tokens, API key headers, `sk-*`, `AIza*`, `ghp_*`/`github_pat_*`, `AKIA*`/`ASIA*`, `xox*`, and `gsk_*` secrets before truncating error bodies. `_status_code_of()` inspects only typed HTTP status attributes (`status_code`, `status`, `code`), preventing error message text containing numbers like `500` or `404` from misclassifying retry behavior.
3. **Loopback Binding**: `main.py --web` binds to `127.0.0.1` by default. Binding to a non-loopback interface requires `--insecure-remote`.
4. **Bearer Token Authentication & Atomic Token File**: Every `/api/*` request requires `Authorization: Bearer <token>`, and WebSocket connections require the `bearer.<token>` subprotocol (which is redacted to `bearer.[REDACTED]` in `scope["subprotocols"]` immediately upon receipt). `~/.pair_programmer` is enforced at `0700`, `~/.pair_programmer/token` at `0600`, and stalled/empty token files are recovered atomically. The web studio stores the token in `sessionStorage` for the active tab.
5. **Separated Auth/Unauth Rate Quotas & WebSocket Idle Timeout**:
   - Authenticated REST traffic uses per-IP bucket `auth:<ip>` (60 req/min); unauthenticated traffic uses `unauth:<ip>` (20 req/min) so unauthenticated floods cannot starve a valid local operator.
   - WebSocket handshakes are rate-limited (`ws:<ip>`, 10/min), concurrent clients are capped at 10, and idle WebSockets close automatically after `WS_IDLE_TIMEOUT_SECONDS = 60.0`.
   - Frontend `/api/status` calls triggered by WebSocket events are debounced to at most 1 request per 2 seconds, and `SprintRunCoordinator` serializes `/api/sprint/start` with a single unified `run_id`.

## 5. Terminal, Git & Supply Chain Hardening

- **ANSI Sanitization**: `strip_ansi()` removes CSI, OSC (including OSC 52 clipboard writes), and C0/C1 control characters from model outputs, tool outputs, paths, and error messages before rendering or logging.
- **Detached Git Metadata & Secret Content Scanner**: `GitManager` stores repository metadata outside the workspace (`<workspace>.pair_programmer_git`), uses `build_sanitized_environment()`, disables hooks (`core.hooksPath=/dev/null`) and external diff/SSH helpers, preserves existing `.gitignore` entries, and unstages any file matching `DEFAULT_EXCLUDES`, exceeding 5 MiB, or matching `_SECRET_CONTENT_PATTERN` (PEM private keys, `sk-*`, `ghp_*`, `AKIA*`, `AIza*`) even if `.gitignore` is overridden in the workspace.
- **Reproducible Lockfile & CI Audit Policy**: Runtime dependencies are pinned in `pyproject.toml` and `requirements.lock` (alongside `frontend/package-lock.json`). CI installs from `requirements.lock` and fails the build on `pip-audit -r requirements.lock` or `npm audit --audit-level=high` findings.
