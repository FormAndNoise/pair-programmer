# Security Architecture & Threat Model

This document defines the security boundaries, threat model, and operational controls of the Dual-Model Pair Programming Agent.

## 1. Threat Model

The harness executes untrusted code and tool calls generated by external Large Language Models (LLMs). The primary adversary vectors are:

1. **Indirect Prompt Injection & Malicious Model Output**: A compromised or hallucinating LLM attempts to execute arbitrary host commands, exfiltrate environment credentials, or tamper with test suites to force false-positive completions.
2. **Sandbox Escape & Resource Exhaustion**: Generated code attempts path traversal (`../`), symlink escape, fork bombs, memory exhaustion, or infinite output floods.
3. **Cross-Site WebSocket Hijacking (CSWSH) & Local API Abuse**: A malicious web page open in the operator's browser attempts to connect to `127.0.0.1:8000` to steer the sprint or read workspace source code.
4. **Terminal & Log Injection**: Model output or filenames contain ANSI/OSC escape sequences designed to spoof terminal prompts or manipulate the operator's clipboard.

## 2. Execution Sandbox Boundaries

### 2.1 Docker Container Sandbox (`DockerSandboxRunner` — Recommended Default)

Live sprints default to `SANDBOX_MODE=docker`. Each `run_command` invocation executes inside a fresh, disposable container with the following controls:

| Control | Flag / Mechanism | Purpose |
|---|---|---|
| Network Air-Gap | `--network none` | Blocks outbound data exfiltration and arbitrary downloads. |
| Read-Only Rootfs | `--read-only` + `--tmpfs /tmp:rw,noexec,nosuid,size=64m` | Prevents container rootfs persistence and binary drops in `/tmp`. |
| Unprivileged User | `--user 65534:65534` | Runs container processes as `nobody:nogroup` instead of `root`. |
| Capability Drop | `--cap-drop=ALL` + `--security-opt no-new-privileges` | Drops all Linux capabilities and blocks setuid privilege escalation. |
| Resource Ceilings | `--memory 512m --memory-swap 512m --cpus 1.0 --pids-limit 128 --ulimit nofile=1024:1024` | Mitigates fork bombs, swap thrashing, and descriptor exhaustion. |
| Init & Reaping | `--init` + `--rm` + startup `_reap_orphaned_containers()` | Reaps zombie processes and removes containers on timeout or crash. |
| Image Digest Pinning | `SANDBOX_REQUIRE_DIGEST=1` | Rejects mutable image tags unless pinned to `@sha256:<64-hex>`. |

### 2.2 Local Process Sandbox (`SandboxRunner` — Explicit Opt-In)

When `SANDBOX_MODE=local_process` is used:
- **Live mode requires `--unsafe-local`** on the CLI and prints a prominent warning banner.
- **No OS-level filesystem or network namespace isolation exists** in `local_process` mode. Path confinement (`resolve_path`) applies only to the structured file tools (`read_file`, `write_file`, `patch_file`, `list_dir`), not to arbitrary Python code executed via `run_command`.
- Commands execute with `shell=False` (`shlex.split` argv tokenization), scrubbed environment variables, process-group / Windows Job Object termination on timeout, and bounded pipe readers.

### 2.3 Environment Scrubbing

Both runners strip all host environment variables matching sensitive patterns (`*_KEY`, `*_TOKEN`, `*_SECRET`, `*_PASSWORD`, `AWS_*`, `GCP_*`, `GOOGLE_*`, `AZURE_*`, `GITHUB_*`, `HF_*`, `ANTHROPIC_*`, `OPENAI_*`, `GEMINI_*`, `OPENROUTER_*`, `GROQ_*`) and dangerous dynamic loader variables (`LD_PRELOAD`, `PYTHONSTARTUP`, `PYTHONINSPECT`, `GIT_SSH_COMMAND`, etc.) before spawning child processes.

### 2.4 Path Confinement & Symlink Protection

- `resolve_path()` resolves target paths against `workspace_dir` and raises `PermissionError` on traversal outside the workspace.
- `read_file`, `write_file`, and `patch_file` reject symbolic links in the target path or any intermediate workspace parent directory, verify the opened file descriptor path, and perform atomic writes via `tempfile.NamedTemporaryFile` + `os.replace`.
- `list_dir` disables symlink traversal (`followlinks=False`) and skips symlink entries.

## 3. Definition of Done (DoD) & Adversarial Review Integrity

To prevent an Implementer model from gaming the quality gates:

1. **RED-Phase Test Pinning**: Immediately after the RED phase, `BacklogManager.snapshot_test_hashes()` records SHA-256 digests of all test files (`tests/**/*.py` and `test*.py`). During `verify_dod()`, any modification, addition, or deletion of pinned test files fails the gate.
2. **Standard Library Shadowing Check**: `verify_dod()` verifies that the workspace does not contain files or directories shadowing `unittest`, `compileall`, `site`, `sitecustomize`, or `usercustomize`.
3. **Harness Smoke Check**: Before running agent tests, the harness runs an independent Python smoke check with trusted `PYTHONPATH`.
4. **Strict Cross-Model Review**:
   - Self-approval (`test_model == impl_model` or mismatched response model attribution) is rejected.
   - Approval requires a standalone `\bLGTM\b` token without preceding negations (`not`, `no`, `cannot`, `almost`, `except`) or post-`LGTM` blocking caveats (`however`, `but`, `fix`, `must`, `error`, `fail`, `todo`).

## 4. Web Studio Security

1. **Loopback Binding**: `main.py --web` binds to `127.0.0.1` by default. Binding to a non-loopback interface requires `--insecure-remote`.
2. **Bearer Token Authentication**: Every `/api/*` request requires `Authorization: Bearer <token>`, and WebSocket connections require the `bearer.<token>` subprotocol. Tokens are read from `PAIR_PROGRAMMER_TOKEN` or generated with CSPRNG (`secrets.token_urlsafe(32)`) at `~/.pair_programmer/token` (`0600` permissions). Comparisons use `hmac.compare_digest`.
3. **Origin Enforcement**: State-changing REST endpoints (`POST /api/*`) and `/ws` upgrades validate the `Origin` header against the local allowlist (`http://localhost:5173`, `http://127.0.0.1:5173`, `http://localhost:8000`, `http://127.0.0.1:8000`).
4. **Rate & Connection Caps**: REST requests are limited to 60 requests/minute per IP; concurrent WebSocket clients are capped at 10; `EventBus` history uses a bounded 1,000-event ring buffer.

---

## 5. Terminal & Git Hardening

- **ANSI Sanitization**: `strip_ansi()` removes CSI, OSC (including OSC 52 clipboard writes), and C0/C1 control characters from model outputs, tool outputs, paths, and error messages before rendering or logging.
- **Detached Git Metadata & Secret Exclusion**: `GitManager` stores repository metadata outside the agent workspace (`<workspace>.pair_programmer_git`), disables hooks (`core.hooksPath=/dev/null`) and smudge/clean filters, uses `--no-verify`, and blocks staging of `.env*`, `*.pem`, `*.key`, `id_rsa*`, and files larger than 5 MiB.
